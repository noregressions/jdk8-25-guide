This chapter is about how applications *reach users*, and four mechanisms from the JDK 8 era ended together: Oracle stopped shipping a standalone JRE and Java Web Start with JDK 11; JavaFX left the JDK the same release to live as OpenJFX; and applets — long dead in browsers — had their API terminally deprecated in JDK 17 and removed in JDK 26.

---

## What happened — including an honest vendor caveat

Building this chapter's verification produced a finding worth more than the original claim: **how much a team "loses" here depends on which JDK 8 distribution they are leaving.** Web Start and bundled JavaFX were historically Oracle/Sun JDK features — Eclipse Temurin's JDK 8 never shipped either, and the same is true of several other OpenJDK-based 8 builds. A team migrating off Oracle JDK 8 genuinely loses launch infrastructure; a team already on Temurin or Corretto 8 never had it. Check what your *actual* JDK 8 provides before writing the migration ticket — "distribution changes" is as much about the vendor axis as the version axis.

The vendor-independent parts: there is no standalone JRE to bundle from any current distribution — the "install Java once, run everything" deployment model is over, replaced by per-application runtimes. And the Applet API's terminal deprecation (verified below: the `[removal]` warning fires on JDK 25's compiler and not JDK 8's, for identical source) completed in JDK 26 with the API's removal.

---

## Detect

Inventory, not grep: what does your organisation ship via Web Start (`.jnlp` files are the searchable artefact), what assumes a system-wide JRE exists, what imports `javafx.*`, and what extends `Applet`? For the JavaFX case:

```bash
grep -rEn "import javafx\.|\.jnlp|javaws|extends J?Applet" src/ deploy/
```

---

## Fix

Per mechanism: the missing JRE becomes **`jlink`** (a custom minimal runtime image shipped with the application) or simply bundling a full JDK — either way, the runtime is now part of your artefact, which also ends the "which Java does the customer have" support genre. Web Start's auto-update niche is filled by ordinary installers plus update frameworks, or by not shipping desktop-installed software at all. JavaFX continues healthily as OpenJFX — add the Maven/Gradle dependencies explicitly and the application is back in business. Applets have no migration path; the fix is a web application, and has been for a decade.

## Worked example

From [`examples/33-distribution-changes`](https://github.com/noregressions/jdk8-25-guide/tree/main/examples/33-distribution-changes), verified on Temurin 8u502 and Temurin 25.0.4:

```
Java Web Start (javaws) and JavaFX bundling, this vendor's JDK 8 build:
  javaws: absent (Temurin never bundled this even on JDK 8 — Oracle-only historically)
  javafx: absent (same caveat)

Applet API deprecation warning, JDK 8:
  Applet.java:5: warning: [serial] serializable class Applet has no definition of serialVersionUID
  1 warning

Applet API deprecation warning, JDK 25 (identical source):
  Applet.java:5: warning: [removal] Applet in java.applet has been deprecated and marked for removal
  Applet.java:5: warning: [serial] ...
  2 warnings
```

The absent-on-8 lines are the caveat made visible: this vendor's "before" never contained the things the folklore says the migration removes.
