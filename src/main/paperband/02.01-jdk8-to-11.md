chapter: "2.1"
title: "JDK 8 to 11: The Structural Break"
description: "The module system, the Java EE removal, and the end of the JDK you knew — most of this migration's structural risk lands in these three releases."
---

The 8→11 span is where the platform changed shape. JDK 9's module system rewrote visibility and the runtime image; JDK 11 removed entire package families and ended the standalone JRE. Most of what makes an 8→25 migration *feel* large lands in these three releases — the later spans are more numerous but less structural.

| Change | Level | Chapter |
|---|---|---|
| JDK layout: `rt.jar`, `tools.jar`, `jre/` gone (9) | Environment | 3.32 |
| Extension/endorsed mechanisms rejected (9) | Won't Start | 3.4 |
| System classloader no longer a `URLClassLoader` (9) | Crash | 3.9 |
| Split packages illegal on the module path (9) | Crash | 3.11 |
| GC logging: unified logging replaces `PrintGC*` (9) | Won't Start (partly) | 3.3 |
| Default GC: Parallel → G1 (9) | Runs But Wrong | 3.19 |
| CLDR locale data becomes default (9) | Runs But Wrong | 3.17 |
| Version string loses the `1.` prefix (9) | Runs But Wrong | 3.23 |
| `_` becomes a keyword (9) | Recompile | 3.26 |
| Default keystore type JKS → PKCS12 (9) | Environment | 3.36 |
| Finalisation deprecated (9) | Runs But Wrong (deferred) | 3.22 |
| `jhat` removed (9); `javah` removed (10) | Environment | 3.34 |
| Container-aware ergonomics (10; backported to 8u191) | Environment | 3.37 |
| **Java EE and CORBA modules removed (11, JEP 320)** | Crash | 3.6 |
| `wsimport`/`wsgen`/`schemagen` removed (11) | Environment | 3.34 |
| Standalone JRE and Web Start end; JavaFX unbundled (11) | Environment | 3.33 |
| Nestmates replace bridge methods on recompile (11) | Recompile | 3.31 |
| …which shifts computed `serialVersionUID`s | Recompile | 3.25 |

Also in this span: illegal reflective access begins its long arc — permitted-with-warnings from 9, which is why applications "worked fine on 11" and still crash on 17+ (the enforcement dates are in the next two chapters, but the *cause* is JDK 9's encapsulation).

**If this is your hop:** the two items that dominate real 8→11 migrations are the Java EE removal (3.6 — mechanical once you know the Jakarta coordinates, Appendix B) and reflective-access warnings from frameworks (upgrade them now, before 16+ turns warnings into errors — 3.5). Run the flag audit (1.5) before anything: the GC-logging and ext-dirs failures are cheap to find and startup-fatal. And note the container caveat — if your JDK 8 images predate 8u191, heap sizing changes underneath you (3.37).

Tools for this span: `jdeps` (1.1) and `jdeprscan` (1.2) find nearly everything above; the trial compile finds the rest.
