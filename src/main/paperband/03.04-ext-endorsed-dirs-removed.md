| | |
|---|---|
| **Level** | Won't Start |
| **Introduced** | JDK 9 (JEP 220 — Modular Run-Time Images) |
| **Symptom** | `Error: Could not create the Java Virtual Machine.` with an explicit, named message |
| **Detect** | Grep startup scripts and wrapper configs for `ext.dirs`, `endorsed`, `Xbootclasspath` |

This is the Won't Start category's sleeper. Nobody *decides* to use the extension mechanism in 2026 — but launch scripts written in the WebLogic and WebSphere era did, and those scripts get copied forward through a decade of redeployments precisely because they work. On JDK 8 these flags are quietly accepted. On JDK 25:

```
-Djava.ext.dirs=/tmp is not supported.  Use -classpath instead.
Error: Could not create the Java Virtual Machine.
```

---

## What happened

The extension directory (`java.ext.dirs`) and endorsed-standards override (`java.endorsed.dirs`) were pre-modules mechanisms for injecting JARs into the platform itself — below the application classpath. JEP 220's modular run-time images (JDK 9) eliminated the directories those mechanisms depended on, and rather than silently ignoring the flags, the launcher rejects them by name and refuses to start the VM.

Unlike the obsolete GC flags of Chapter 3.1, the error here is at least self-describing — each flag gets an explicit message naming the replacement approach. What it shares with the rest of the category is timing: the failure happens before `main()`, so there is nothing in application logs, only launcher stderr.

Two nuances worth knowing. First, on JDK 8 these flags produced **no warning at all** — they were fully supported, so there was never a deprecation nudge in your logs to prompt cleanup; the first signal anyone gets is the target JDK refusing to boot. Second, the commonly confused sibling `-Xbootclasspath/a:<path>` behaves differently: it *appends* to the boot class path rather than replacing endorsed standards, and it is still accepted on JDK 25. An audit hit on `Xbootclasspath` needs a closer look rather than reflexive deletion — the `/p:` (prepend) form is gone, the `/a:` form survives.

---

## Detect

```bash
grep -rE "ext\.dirs|endorsed|Xbootclasspath" \
  deploy/ docker/ *.sh *.conf setenv* standalone* catalina*
```

Target the ancient corners deliberately: application-server launch scripts (`catalina.sh`, `standalone.sh`, `setenv.sh`), service wrapper configurations (Tanuki-style `wrapper.conf`), and anything with a copyright header from the 2000s. These flags survive precisely where nobody has looked in years.

---

## Fix

Put the JARs on the classpath (or module path) like any other dependency — that is the entire fix, and the error message says as much. There is no endorsed-override mechanism any more; if the *reason* the JAR was in `endorsed` was to override a platform API version, note that the most common candidates — JAXB and the other Java EE modules — left the JDK entirely in JDK 11, so the override becomes an ordinary dependency declaration; Chapter 3.6 covers those removals and their Jakarta replacements.

While you are in the file, check what *else* the JARs in those directories were: extension directories were a popular home for JDBC drivers, crypto providers, and vendor agents, and each of those needs an explicit new home on the classpath.

---

## Worked example

From [`examples/04-ext-endorsed-dirs-removed`](https://github.com/noregressions/jdk8-25-guide/tree/main/examples/04-ext-endorsed-dirs-removed), verified on Temurin 8u502 and Temurin 25.0.4. Both flags: silently accepted, exit 0 on JDK 8 — and on JDK 25:

```
JDK 25 with -Djava.ext.dirs=/tmp -version:
  -Djava.ext.dirs=/tmp is not supported.  Use -classpath instead.
  Error: Could not create the Java Virtual Machine.
  exit=1

JDK 25 with -Djava.endorsed.dirs=/tmp -version:
  -Djava.endorsed.dirs=/tmp is not supported. Endorsed standards and standalone APIs
  in modular form will be supported via the concept of upgradeable modules.
  Error: Could not create the Java Virtual Machine.
  exit=1
```

The `-Xbootclasspath/a:` control run started normally on both JDKs — the audit needs to distinguish the flags, not delete on sight.
