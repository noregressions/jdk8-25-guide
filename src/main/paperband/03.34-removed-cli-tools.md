```
javah         present    absent
jhat          present    absent
rmic          present    absent
wsimport      present    absent
wsgen         present    absent
schemagen     present    absent
pack200       present    absent
unpack200     present    absent
```

Eight for eight. Each of these is an executable some build step, code generator, or ops script calls by name — and the failure is the shell's, not Java's: `command not found`, in whatever half-logged corner of CI the step runs.

---

## What happened

Each tool left when its reason to exist did. `javah` (native header generation) was folded into the compiler as `javac -h` in JDK 8 and removed in 10. `jhat` (heap-dump browsing) was obsolete next to real profilers and left in 9. The Web-Service generators — `wsimport`, `wsgen`, `schemagen` — departed with their Java EE modules in JDK 11 (Chapter 3.6). `pack200`/`unpack200` went with their format in JDK 14 (Chapter 3.15). `rmic` static stub generation had been unnecessary since dynamic stubs arrived — the tool outlived its purpose by fifteen years before JDK 15 removed it.

The migration risk profile is classic build-archaeology: these invocations live in Maven `exec` plugin blocks, Ant targets, `Makefile`s, and generator scripts written by someone who left in 2013, running unnoticed because they never fail — until the JDK under them changes.

---

## Detect

```bash
grep -rEn "javah|jhat|rmic|wsimport|wsgen|schemagen|pack200|unpack200" \
  pom.xml build.xml *.gradle Makefile scripts/ ci/ .github/
```

Word-boundary false positives are possible (`schemagen` inside longer names); the hit list is short enough to eyeball.

---

## Fix

Per tool: `javah` → `javac -h <dir>` (same output, built into the compiler you already run). `jhat` → JDK Mission Control, VisualVM, or `jhsdb` for heap-dump analysis. `wsimport`/`wsgen`/`schemagen` → the same tools as external dependencies from the JAX-WS/JAXB reference implementations (Maven plugins exist: `jaxws-maven-plugin`, `jaxb-maven-plugin`) — the generators still exist, they just aren't JDK residents anymore. `rmic` → delete the step; dynamic stubs have covered it since JDK 8. `pack200` → delete the step and ship plain JARs (Chapter 3.15 covers the distribution question).
